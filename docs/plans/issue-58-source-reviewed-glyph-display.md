# #58 — Source-reviewed Unicode display for empty IIP glyph references

## Research / authenticated inputs (before TDD)

- Depends on #108 / PR #109: pinned `Brown-University-Library/iip-texts@0b7dc8358ccdfd0c9391f049da4839fbd91c26e5`, EpiDoc Git tree `4445c4878873227c73ead5e8b94f9e3487c28c3b`, **5,535 records**. Its actual pinned census reports **1,955 empty referenced `g` elements / 503 records / 153 distinct XML-decoded refs**: transcription 1,321, diplomatic 102, segmented annotation 532; plus 7 empty unreferenced and 1,352 authored nonempty referenced `g`. The source census is not itself a native reading and all 1,955 must not be counted as visible primary slots.
- Production currently preserves empty `g` in source `markup kind=glyph ref` over synthetic `glyph_ref` slots with **empty** source `glyph`. Existing opt-in `text-orig-refs-full` renders source-label `((ref))`, but no reviewed Unicode. Its primary-reference-token extraction explicitly skips competing `transcription_segmented` annotations and never changes `text-orig-full`.
- Genuine Brown examples: `masa0286.xml` (Git blob `b90768fcfa66c525b62372639a6c6536a6251355`): transcription `phoen-gaml`, `phoen-delt`; `masa0290.xml` (blob `2b601a4e878b750527e89219584e6b2883b3fb5a`): `phoen-wau`, `phoen-mem`.
- Unicode's published Phoenician block names list (https://www.unicode.org/charts/PDF/U10900.pdf and https://www.unicode.org/Public/17.0.0/charts/nameslist/n_10900.html, if available) confirms individual letters ALF/BET/GAML/DELT/HE/WAU/YOD/MEM/NUN/SEMK and numbers ONE/TEN/TWENTY/ONE HUNDRED/TWO/THREE. **Only exact one-code-point correspondences** are eligible. Unicode character identity is not a claim of exact ancient handwriting/facsimile shape.
- First reviewed map comprises 10 source-named Phoenician letters plus 6 numbers: `phoen-aleph` U+10900; `phoen-bet` U+10901; `phoen-gaml` U+10902; `phoen-delt` U+10903; `phoen-he` U+10904; `phoen-wau` U+10905; `phoen-yod` U+10909; `phoen-mem` U+1090C; `phoen-nun` U+1090D; `phoen-semk` U+1090E; `phoen-1` U+10916; `phoen-10` U+10917; `phoen-20` U+10918; `phoen-100` U+10919; `phoen-2` U+1091A; `phoen-3` U+1091B. The other **137 observed refs** receive explicit source-label fallback, especially `phoen-4`, `phoen-6`, `phoen-???`, stroke-count, iconography and unrecognized symbols. No substitutions based on visual resemblance or numerical repetition.

## Research → plan → RED TDD → implement → gates

1. Commit a deterministic, reviewed **complete 153-ref policy** (explicit Unicode scalar or explicit fallback), with Unicode Names List basis and source identity. Keep it converter-owned in Python/package data, **not** a generated semantic sidecar. Make policy coverage equality testable against the authenticated pinned census; unseen *empty* ref must fail closed rather than silently invent a glyph. Distinguish source XML attr (not raw lexical source quoting).
2. RED-first tests: primary synthetic glyphs from `masa0286/masa0290`, numerals, source-labelled `bird`/`phoen-4` fallback, unknown ref, escaped source labels, nonempty `<g ref>+</g>`, bare empty `<g/>`, segmented annotation overlap, primary vs secondary edition, RTL rendering, unchanged `glyph`/`text-orig-full` and byte-stable native TF outputs. Run dedicated pytest RED before implementing production mapping.
3. Implement additive **derived display feature(s) and opt-in text format(s)**; preserve existing source markup `ref`, `glyph`, `text-orig-full`, `text-orig-refs-full`, sign/slot/edge identity, and reading branch precedence. The app should use a documented, researcher-readable normalized Unicode/fallback format after native app tests, without concealing translation or commentary layers.
4. Enforce all 153 policy values against `glyph-source-census.json` in the existing pinned workflow after #109 is merged; require exact-head Ruff, strict MyPy, fixtures, authenticated six canaries, all 5,535 sources converted twice and reloaded with byte-identical .tf, browser, taxonomy and full raw/compiled Context-Fabric parity. No skips.
5. Logically independent skeptical post-gate review must check genuine Brown XML, selected vs segmented source, source/derived provenance, unsafe HTML text, Unicode names and fallback coverage. An autonomous **user-facing E2E** from clean installation/browser is required before 0.1.0 release; this bounded feature PR alone does not certify release.

Non-goals: infer missing source characters, replace palaeography with facsimile claims, coerce arbitrary numbers/strokes to multi-code-point display, revise EpiDoc `ref`, or create network-dependent runtime metadata.
