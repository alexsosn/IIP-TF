## Bounded production decision

Add **native TF `person` nodes** only for *attested textual* `ENTITY entity_kind=person` with `ref="persons.xml#ID"` and a matching register `person xml:id`; unique per inscription and source ID. Add directed native edge `person_ref` **entity→person**, and register-source features `person_id`, `person_name` (literal first `persName`), `sex` (source ISO 5218 code as string), `faith` (verbatim, no normalization), `person_name_variants` (additional register spelling variants, only if present). New nodes reuse the entity's existing slots and never create glyphs. Preserve original entity `ref`, and source `name_lang` (name origin) separately from person sex/faith and sign language. Do **not** link `respStmt` or revision contributors, fabricate missing persons, or merge same-name individuals across records. Fail closed on malformed/duplicate `xml:id` or source target mismatching its inscription prefix; unknown textual target is retained as unresolved evidence rather than assigned a forged person.

Make an optional source-register augmentation step `attach_person_register(ir, register)`, used by **the production CLI** when the sibling `data-keep/persons.xml` exists or an explicit `--persons-register` is provided, and used by **both passes of pinned native validation**. Existing parser, fixtures, and readers of EpiDoc without auxiliary register remain backward compatible; conversion from a full IIP repository automatically builds links. New `person` nodes and `person_ref` edges appear in native TF's regular `otype`, `oslots`, and edge features, with no semantic sidecar. All names/faith copied verbatim. Provenance: pinned native gate hashes register bytes with real Git blob framing and compares to `bce14d...`.
