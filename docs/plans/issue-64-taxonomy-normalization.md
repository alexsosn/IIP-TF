# Issue #64 — source-backed taxonomy normalization and provenance

## Research on real pinned Brown source

- Original Brown pinned `iip-texts` revision `0b7dc8358ccdfd0c9391f049da4839fbd91c26e5`, `include_taxonomies.xml` blob `c273ee4f0c8e751fca3274c7ce2d1e6ec5d60637`: 6 IIP vocabularies with **142 active categories** (23 category-like elements inside XML comments are NOT active); original root is TEI `classDecl` and some categories nested.
- Existing `src/iip_tf/taxonomy_audit.py` already authenticates the Git blob, parses active category IDs and labels, checks no ID reuse across vocabularies, and audits every native source value for 5 features `object_type` (`IIP-form`), `material`, `genre`, `condition`, `religion`. **Reuse this parser rather than introducing a competing taxonomy source of truth.**
- Existing full pinned audit distinguishes whitespace-separated `@ana` IDs: **402** occurrences fully resolving, **126** partially resolving, **2** without a resolvable member. Those 530 source occurrences cannot be forced into a single category. Other scalar source values have optional leading `#`, sometimes different case/spacing or wrong taxonomy. Do not apply fuzzy/case-folded classification or invent IDs. `beth0002` original inscription `msItem/@ana="#jewish"`; individual `persons.xml` `faith="Jewish"` is a **different provenance field**.

## Implementation policy / compatibility

Introduce a pure, opt-in per-record `resolve_taxonomy_features(ir, registry)` after metadata parsing and before TF write, **only when authenticated taxonomy XML is provided or detected alongside the full Brown source**. For each of the 5 supported `INSCRIPTION` features, preserve the verbatim original in `<field>_original`. Normalize `<field>` to the exact taxonomy ID (strip only leading `#` IDREF syntax) for a single resolved token, or ordered **space-separated IDs** for *all-resolved multivalued* source fields. If any token is unresolved or belongs to the wrong taxonomy, **omit** normalized `<field>` entirely; retain `_original` and a bounded diagnostic. This all-or-nothing policy avoids silently declaring a partially known attribute fully classified. Preserve token order and duplicates. No changes to `IRSign`, original translations, `name_lang`, source `person` graph, glyph/slot topology. Empty and absent source features remain absent, no forged category.
- Preserve old `F.<field>` raw behavior on **standalone EpiDoc-only** CLI conversion without `include_taxonomies.xml`; document this explicit mode difference. Never silently load a network vocabulary or a nonpinned arbitrary source in the pinned build.
- Pinned native builds auto-load and authenticate the taxonomy blob in BOTH independent parses. A source taxonomy audit reads `F.<field>_original` as its raw inventory when normalization was applied; otherwise it retains the prior `F.<field>` mode for old outputs. Pin source taxonomy + corpus hashes, preserve exact previously audited source value counts and 402/126/2 multivalue invariants. Pinned canary `beth0002 religion='jewish', religion_original='#jewish'`; separate native `person` faith `Jewish`.
- The original source taxonomy hierarchy may be expressed via category identifiers like `stone.marble`; do **not** claim all nested TEI taxonomies can be reconstructed from dotted IDs. Research parent edges separately before adding category ontology nodes. Category IDs and labels remain queryable via authenticated `taxonomy_audit` in this bounded slice. No speculative hierarchy inference.
